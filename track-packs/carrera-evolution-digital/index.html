Catalogue coverage is complete for the documented scope; exact physical geometry is not.

This pack covers the listed Carrera catalogue sections, with separate product packaging, component variants and system compatibility. Core flat pieces have mathematically consistent nominal geometry. Special pieces have explicitly illustrative artwork and cannot be used to claim snapping, lane lengths or physical fit. There is no app importer yet.

The first design study used provisional 198/99 mm values. This expanded pack uses a 200 mm road / 100 mm lane-spacing nominal grid, consistent with the manufacturer’s rounded radial families. Neither has been established as exact mould dimensions. The old study remains intact.

Dimension-driven piece authoring

Choose a straight, curve, straight border or curved border; supply dimensions in millimetres. Lane spacing is centre-to-centre between slots. Track width and lane spacing are independent; edge margins are calculated or explicitly supplied. Uneven lane spacing can use an array of slot offsets. Geometry, SVG, connector lane positions and lane lengths are derived from the same definition.

A 200 mm road with two lanes spaced 100 mm apart has slots at 50 and 150 mm. A 198 mm road with the same spacing has slots at 49 and 149 mm. Changing lane spacing must not silently change the road width.

The accompanying authoring utility accepts JSON dimensions and outputs piece.svg and geometry.json. This is an authoring demonstration, not the app’s future visual piece editor. Special switches, height profiles and freeform outlines require additional templates.

Run from the extracted bundle: node tools/geometry.cjs examples/custom-curve.json custom-output.

Save user edits as a new revision in a personal pack. Existing layouts retain their embedded definitions. Connector compatibility compares actual lane positions, not only a brand label.
